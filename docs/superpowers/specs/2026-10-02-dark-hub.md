# Dark (Ink) hub (2026-10-02)

Phase 5 ("Widget 2.0"). Extends §4 of `2026-10-01-app-hub-design.md`
("Paper only for now; Ink follows in a later pass using the same tokens").

## What

The OpenFlow window gets an Ink (dark) theme. It follows the **same setting
as the widget**, `[widget] appearance`:

| Setting | Hub |
|---|---|
| `paper` (default) | Paper, as today |
| `ink` | Ink |
| `auto` ("Match system") | Ink while macOS is in Dark Mode, else Paper |

No new setting and no new mode: the hub and the widget always match. The
rule is the widget's own (`ui/widget_theme.resolve`).

## Switching live

The window re-checks the theme, without a restart, when:

- Settings › Widget › Appearance changes (the click that changes it);
- `config.toml` changes on disk (the widget's menu writes it via the
  daemon): a `QFileSystemWatcher` on the file and its folder (atomic saves
  replace the file);
- macOS switches light / dark (`QStyleHints.colorSchemeChanged`);
- the window comes forward (belt and braces).

Checks are debounced (150 ms). On a change the window rebuilds its sidebar
and pages in the new theme and shows the same page again, on the same tab /
Settings section (`Page.view_state()` / `restore_view()`). Pages build their
styles once, so a rebuild is simpler and safer than re-styling every widget.
Unsaved text in a field (e.g. a half-typed dictionary word) is lost on a
switch; switches are rare and user-initiated, so that is accepted.

The hub reads `config.toml` only; it never writes it for the theme.

## Look

- All colours live in `ui/hub/style.py` as two palettes with the same token
  names (`PAPER_PALETTE`, `INK_PALETTE`); `apply_theme()` rebinds the module
  names, and pages read `S.<TOKEN>` while building. Tooltips, menus,
  combo-box popups and scrollbars follow via an application stylesheet and
  palette.
- Paper keeps today's values exactly.
- Ink is the brand book's warm near-black, never blue-grey: panel `#1A1814`,
  chrome a step darker, cards a step lighter, muted the widget's Ink muted
  `#A39A8E`. Text is the widget's Ink text `#FAF7F2`, read from
  `ui/widget_theme.INK` so hub and widget always match (user decision
  2026-10-05).
- **One accent, `#E5402F`, in both themes** (Decisions 2026-10-02). Ink
  only changes its tints: soft fills, accent-coloured text (lighter, for
  contrast on dark), chart ramps (heatmap and stacked bars run dark → red →
  light).
- Home's banner stays the "inverted" surface: Ink on Paper; on Ink a raised
  dark stage, so it still reads as a banner.
- Ink text pairs meet WCAG AA (4.5:1). Paper's known-low pairs (muted text,
  sage) are unchanged and pinned at ≥ 3:1 so they can't get worse.

## Rules (tested)

- No hex, `rgb()`, named colour or numeric `QColor` anywhere in `ui/hub`
  except `style.py`.
- No colour token captured at import (module constant, class attribute,
  default argument): it would keep the old theme after a switch.
- Built in Ink, no page (every Insights tab, every Settings section) uses a
  colour that only exists in Paper.
- Live switch rebuilds pages and keeps the place; failures are logged, never
  raised.

## Out of scope

The first-run window and the edit overlay (not part of the hub); a separate
hub-only appearance setting.
