# Widget 2.0: live text, tone chip, actions after a paste

**Date:** 2026-10-02 · **Roadmap:** Phase 5 (feel), first three items
**Base spec:** [`2026-09-30-flow-widget-design.md`](2026-09-30-flow-widget-design.md) (sizes, motion,
pop-up rule, Paper/Ink tokens). Everything below follows it unless it says otherwise.

## Principles for this round

- The widget's resting size and position don't change (idle handle 7 × 40 at 86%, docks as set).
  New UI appears only in the state that needs it, as a pop-up on the screen-facing side, 10 pt away.
- One accent (`#E5402F`), Paper/Ink surfaces, Fraunces for content and Geist for UI.
- Nothing new to manage: no settings, no modes. Live text is on whenever the take is streamed.
- The widget never takes focus (non-activating panel); clicks on pop-ups and menus leave the
  user's app frontmost, so paste, undo and redo go to the app they were typing in.
- Never block the audio path, and never lose the text.

## 1 · Live text while speaking

**What you see.** While recording (hold or hands-free), as soon as Sarvam's realtime stream returns
words, a panel appears beside the recording pill with the last two lines of what you've said, in
Fraunces 15.5 pt on the theme surface. Older words fade: when the text runs past two lines the top
line fades from 30% to full opacity left to right, and a new line slides the text up over 180 ms.
The panel is a fixed size (340 wide, like the card; 2 lines) from the moment it appears, so it never resizes as words
arrive or get revised. It stays, frozen, while the take is processed, and fades out (140 ms) when
the result pastes or anything else takes the pop-up slot.

No stream (streaming off, failed to connect, batch fallback) or no words yet: nothing new appears;
the waveform is exactly as today. "Can't hear you" and the first hands-free hint keep priority over
the panel. Partials are a preview only: what pastes is still the finals (or the batch result) after
cleanup.

**How.**
- `stream_stt.StreamingSession` assembles the take so far: finals in `utterance_idx` order plus the
  open utterance's partial, and calls `on_partial(text)` with that whole text on every partial and
  final (it already switches `stream_type` to `balanced` when `on_partial` is set). It runs on the
  stream's receive thread, never the audio callback.
- `flow_state.LiveText` (pure, thread-safe) throttles: `offer(gen, text)` only stores the latest text
  (no I/O); the widget pump (already 20 Hz) calls `due(now)` and sends at most one message per
  125 ms (≤ 8/s), only the newest text, only for the current take (`gen`), only while recording. The
  text is cut to its last 240 characters at a word boundary.
- Message (daemon → widget): `{"type":"live","text":"…"}`. The text is never logged.
- Each take gets a new generation, so a late partial from a cancelled or previous stream is dropped.

## 2 · Tone / language chip

**What you see.** A small chip that names the current tone, plus the language when it isn't Auto:
`Casual`, `Professional · Hindi`. Geist 12.5 medium with a ▾, on the theme's secondary fill.
- **Hover** (Dictate tooltip): the chip sits in the red tooltip after the key hint. It is outlined
  in white (filled only under the pointer), so it reads as a control next to the filled key label.
- **Recording**: the chip heads the live-text panel. Without live text it shows only while the
  pointer is over the recording pill (so the waveform-only look stays as today).
- **Click** opens a picker in the pop-up slot (theme surface, like the card): Tone (7 pills, the
  current one filled red) and Language (7 pills). It is the widget's own non-activating pop-up, not
  a `QMenu`: a menu can make OpenFlow the active app, and then the app the user was typing in is no
  longer in front (paste and undo would refuse). Choosing sends the same actions as the right-click
  menu (`set_tone`, and the new `set_language`).
- **F6 flash**: when the cycle hotkey changes the tone (or language), the chip flashes: if a chip is
  on screen it pulses for 600 ms (to red; on the red tooltip, to white with red letters); otherwise a chip pop-up appears beside the widget for 1.4 s
  with the new tone, then fades. The widget doesn't move or resize.

**How.** `config` gains `"language"`. New widget → daemon menu action
`{"action":"set_language","value":"hi"}` (beside the existing `set_tone`). New daemon → widget
message `{"type":"flash"}`, sent by `cycle_tone` / `cycle_lang` after a `config` push. Hovering
from the widget onto an interactive pop-up keeps it open (220 ms grace to cross the 10 pt gap;
held while a chip menu is open).

## 3 · Actions after a paste ("done")

**What you see.** After a dictation pastes, the widget is in a new **done** state for 6 s. At rest
it looks exactly like idle (the red handle). Hovering it shows the Dictate pill (click still starts
a new dictation) and, instead of the Dictate tooltip, an actions pop-up on the theme surface:
**Pasted** (Fraunces) · the take's tone chip **Casual ▾** (= redo in another tone) · **Copy** ·
**Undo**. The window is held while the pointer is on the widget or the pop-up and ends 1.5 s
after it leaves (60 s backstop).

- **Copy** puts the pasted text on the clipboard; the button reads "Copied" for 1.2 s.
- **Undo** runs the existing undo-last-paste (⌘Z in the app it went to, clipboard restored). Undone
  → idle. If undo isn't safe (the app isn't in front, the text before the caret changed, older than
  the paste-undo window), nothing is sent and the pop-up says **Can't undo here** and drops the Undo button (Copy and the tone chip stay; user decision 2026-10-05).
- **Tone chip ▾** ("Rewrite as"): pick a tone → the widget shows processing → cleanup re-runs on the
  take's stored raw transcript (the same `_post_process` the hub's "Run it again as…" uses, in the
  take's language, against its app; never skips cleanup) → the old text is replaced → done again,
  in the new tone (so Copy, Undo and another rewrite work on the new text).

**Replacing the text (the choice).** Replace = undo-last-paste, then paste the new text. If undo
isn't possible we do **not** paste fresh: the new text goes on the clipboard and the card shows
"Couldn't replace · On your clipboard · ⌘V to paste" with Copy (no click-to-paste). Why: undo
refuses for exactly the cases where a fresh paste would land wrong — another app is in front (the
text would go somewhere else), or the user has typed since (the old and new versions would sit side
by side, and the caret is no longer at the old text). Paste-fresh would silently duplicate or
misplace text; the card never loses it and lets the user put it where they mean. When undo succeeds
the new text is pasted into the same target, and its paste becomes the one Undo reverts.

A rewrite that loses the widget to a newer dictation never pastes over it: its text waits as a
queued card (Phase 4 queue). ✕ / Esc during the rewrite discards it. Edit and command mode results
go to idle as today (their raw text is an instruction, not something to rewrite).

**How.** `flow_state`: new state `DONE = "done"`; `pasted(text, take, tone, run)` enters it (only
for the run that owns the widget); `handle_action` adds `copy_last`, `undo_paste`, `redo` (value =
tone) and `hover` (`on` / `off`), all only in DONE; `undo_finished(status)` and the `note` field
(`"cant_undo"`) report back. `FlowHooks` gains `undo_paste` and `redo(take, tone, run)`. Message:
`{"type":"state","state":"done","tone":"casual"}` (+ `"note"`). The daemon keeps the take
(raw, tone, language, target) only in memory, for the done window.

## Messages added (summary)

| Direction | Message |
|---|---|
| daemon → widget | `{"type":"live","text"}` · `{"type":"flash"}` · `state` `done` with `tone`, `note` · `config` + `language` |
| widget → daemon | `set_language` · `copy_last` · `undo_paste` · `redo` (tone) · `hover` (`on`/`off`, done only) |

## Testing

- Unit (no Qt, no network): `LiveText` throttle (≤ 8/s, newest wins, generations, trimming, only
  while recording); `StreamingSession` live-text assembly with a fake socket; `FlowController` DONE
  transitions (enter, expiry, hover hold, copy, undo ok / refused, redo → processing → done / card,
  stale run queued, cancel during redo, start from done).
- Daemon (fakes): paste → done with the take; redo replaces via undo + paste; redo with refused undo
  → clipboard + card; F6 → config + flash; `set_language` menu action; partials → `live` messages.
- Widget (offscreen Qt): live panel fixed size, tail lines, appears only with text; chip label and
  menu actions; flash; done hover pop-up and its buttons; hover grace.
- Offscreen renders (Paper + Ink, 1× and 2×) of: hover with chip, recording with live text,
  recording hover chip, F6 flash, done actions, "Can't undo here", and the not-replaced card.
- On screen after deploy: see the report's checklist.
